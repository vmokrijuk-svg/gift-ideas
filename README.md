# 🎁 Идеи подарков — рабочие заметки

Личный органайзер идей для подарков близким и себе. Работает как PWA: открывается на iPhone, iPad и в браузере, данные хранятся локально + резервная копия в GitHub.

**Живая версия:** https://vmokrijuk-svg.github.io/gift-ideas/
**Репозиторий:** https://github.com/vmokrijuk-svg/gift-ideas

---

## 1. Контекст задачи

Изначальная боль: идеи для подарков расползались по 5–6 местам — закладки в браузере, Apple Notes, Apple Tasks, Telegram «Избранное», Instagram. Нужно было единое место, где:
- есть структура: человек → повод → бюджет → цена;
- можно быстро добавить идею «на ходу»;
- карточки приятны глазу и понятны **без кучи фильтров**;
- есть напоминания (пока не реализовано полностью);
- поддерживаются ссылки, картинки, цены.

Ограничения среды:
- Основная работа — на **корпоративном MacBook** с заблокированными инструментами разработчика (нет Web Inspector, нет доступа к файлам по политике MDM).
- Личные устройства — **iPhone + два iPad**.
- Основная задача ставится и проверяется **на личных устройствах**, а не на рабочем ноутбуке.

Стратегический выбор: **не использовать готовые приложения** (Wisht, Wishy, Moonsift), а собрать **своё** под конкретный сценарий.

## 2. Архитектура решения

**Фронтенд — статический сайт из трёх файлов:**
- `index.html` — разметка;
- `style.css` — внешний вид;
- `app.js` — вся логика.

**Хостинг — GitHub Pages**, публичный репозиторий `gift-ideas`, ветка `main`, корень. Ссылка: `https://vmokrijuk-svg.github.io/gift-ideas/`.

**Данные:**
- Основное хранилище — `localStorage` браузера (ключи `giftIdeas`, `giftPeople`, `giftCollapsedGroups`, `giftSortMode`, `giftLastModified`).
- Резервная копия — файл `ideas.json` в корне репозитория GitHub.
- Синхронизация — **полуавтоматическая**:
  - при старте приложение само подтягивает `ideas.json` из GitHub (`raw.githubusercontent.com`) и сравнивает время модификации;
  - если в GitHub свежее — предлагает загрузить;
  - запись в GitHub вручную: кнопка 📤 скачивает `ideas.json`, пользователь загружает его через веб-интерфейс GitHub.

**Почему не автоматическая запись:** статический сайт не имеет прав на запись в репозиторий без OAuth-прокси (Cloudflare Worker и т.п.). Для тестового проекта это избыточно.

**PWA:** есть `manifest.json` с иконками 192 и 512 px. Устанавливается на iPhone/iPad через «Поделиться → На экран Домой», открывается в полноэкранном режиме.

## 3. Что уже реализовано

### Хранение и структура
- Карточки идей с полями: `id`, `person`, `occasion`, `budget`, `title`, `link`, `image`, `price`, `bought`, `createdAt`, `updatedAt`.
- **Справочник людей** (`giftPeople`) — отдельный массив имён. Нельзя удалить человека, если у него есть идеи.
- Миграция: при первом запуске новой версии люди автоматически собираются из существующих карточек.
- Группировка карточек по людям. Люди сортируются **по количеству идей** (по убыванию), при равенстве — по алфавиту.
- **Сворачивание групп** по клику на заголовок. Состояние хранится в `localStorage` (ключ `giftCollapsedGroups`).

### Форма добавления / редактирования
- Одна форма на два режима: создание и редактирование (определяется скрытым полем `id`).
- Выбор человека из выпадающего списка + кнопка «+ Новый человек», которая показывает поле для нового имени. Новое имя автоматически попадает в справочник.
- Поле «Для кого» **обязательное**.
- Картинка: загрузка из галереи (`<input type="file">`), автоматическое сжатие до 400 px по длинной стороне и качество JPEG 0.7. Хранится как Base64 в поле `image`.

### Просмотр
- **Поиск** по имени, названию и поводу (регистронезависимый).
- **Фильтр** «Только не купленные».
- **Сортировка** внутри групп: по дате (сначала новые) / по сумме (сначала дорогие). Состояние в `localStorage` (ключ `giftSortMode`).
- **Суммы:** в шапке `Всего: X ₽ · Не куплено: Y ₽` (считаются по найденным с учётом поиска, но **без** учёта фильтра «не купленные»). В заголовке группы: `N идей · M куплено · Z ₽`.
- Парсер цен: вытаскивает число из строки («4 990 ₽» → 4990).

### Экспорт / импорт / синхронизация
- Кнопка **📤 Экспорт** — формирует `ideas.json` (`version`, `lastModified`, `ideas`, `people`) и скачивает.
- Кнопка **📥 Импорт** — открывает выбор файла, читает JSON, предлагает заменить локальные данные.
- При старте **авто-проверка GitHub**: если `lastModified` в `ideas.json` новее локального — предложение загрузить.
- Статус-бар под шапкой: «✓ Данные актуальны», «Локальные данные новее», «Офлайн-режим» и т.п.

### Отладка
- **Видимый журнал** (`#debug-log`) — работает даже без Web Inspector. Ловит `window.onerror`, логирует ключевые события.
- Показывается автоматически при критической ошибке, иначе можно открыть вручную.

## 4. Ключевые технические решения и почему так

**Никаких фреймворков (React, Vue и т.п.).** Для личного инструмента это оверкилл. Чистый HTML + CSS + JS, работает везде, не требует сборки.

**LocalStorage, а не IndexedDB.** Данных мало (десятки карточек). Лимит ~5 МБ, но при сжатии картинок до 400 px JPEG 0.7 каждая весит 15–40 КБ — влезет 100+ штук.

**Один `app.js` без модулей.** Работает при открытии `file://` и на GitHub Pages одинаково.

**Inline-обработчики в HTML там, где это критично** (`onclick="openForm()"` и т.п.). Это надёжнее, чем `addEventListener`, который может не сработать, если скрипт упал раньше. Но для полей ввода, которые могут «оживать» до загрузки скрипта (поиск, чекбоксы), — только `addEventListener`.

**Полуавтоматическая синхронизация, а не автоматическая.** Статический сайт не может писать в GitHub без OAuth-прокси. Компромисс: чтение автоматическое, запись — вручную через 📤 + загрузка файла на GitHub.

## 5. Известные ограничения

- **Данные не синхронизируются между устройствами мгновенно.** Разные iPhone/iPad видят разные LocalStorage. Синхронизация через GitHub — при следующем открытии страницы.
- **LocalStorage привязан к браузеру.** Очистка кэша Safari = потеря локальных данных (если нет свежего бэкапа в GitHub).
- **Автоматической записи в GitHub нет.** Каждое изменение требует экспорта + загрузки файла.
- **Корпоративный MacBook не подходит для тестирования.** MDM-политики могут блокировать работу с файлами и Web Inspector.
- **Напоминаний о праздниках пока нет.** Это следующий шаг (см. раздел 6).
